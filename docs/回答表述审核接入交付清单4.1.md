# 回答表述审核接入交付清单4.1

日期：2026-10-22。关联F04/F05/F21/F23。本批接入4.0的11项表述审核，未执行或授予医学审核。

## 使用入口

打开本机 <http://127.0.0.1:8011/audit>，选择 **回答表述 · 4.0**。

每项展示原回答、待核对候选、问题说明、原始引用、来源链接及可展开的文献版本与定位。确认候选、提出修改或驳回均作为独立意见保存，不覆盖原材料。

1. 未填写完整时可保存草稿，重载后继续填写。
2. 提交需要处理意见、审核人姓名、有效时间和理由。确认候选还需核对原文与范围，并明确填写拟采用表述；“填入候选供核对”不会选择决定或自动提交。
3. 提出修改时需填写完整建议表述；驳回可只说明理由，不必填写拟采用表述。
4. 查看历史可对照保存时的意见和材料；导出表述记录包含草稿及提交历史，未保存输入不导出。

当前姓名为填写者声明，尚未接医院身份认证。提交确认不代表临床批准，不会应用候选、改写患者答案、发布知识库或触发模型评分。

## 后端与绑定

- 新增独立的本地表述审核服务与接口，沿用工作台会话和同源写入要求；原资料/题目审核接口及开发纳入流程保持独立。
- 仅加载固定4.0审核包，并核对3.9原始结果、审核队列哈希及每项原句、引用和来源身份，全部11项完整匹配后才可操作。
- 材料内容和归档依据共同生成绑定标识。材料修改后旧意见不自动沿用；旧页面提交及并发覆盖被阻止，当前填写保留。历史追加保存材料快照，不覆盖旧记录。
- 数据库为忽略目录中的`var/wording-reviews.sqlite3`，与旧资料/题目、患者业务库分离；读取页面不会创建审核决定。
- 导出包含当前11项、审核历史及绑定依据，始终保留未应用和未临床批准的标记。

接口前缀：`/api/v1/validation/audit/wording`，提供items、详情、draft、submit、history和export。

实现：`backend/app/retrieval/wording_review.py`、`backend/app/api/wording.py`，注册于`validation.py`；页面为`frontend/validation/audit.html`、`audit.js`、`audit.css`。
