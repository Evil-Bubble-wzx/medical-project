# 账号授权与患者资料后端交付清单1.7

日期：2026-10-20。

本轮进入M3，完成本地开发账号、患者授权及合成患者资料版本保存后端。业务接口已加载到8011工作台，原检索与审核页面不变。本轮没有新增登录或患者管理页面，也没有将患者资料接入模型问答或保存问答结果。

## 已交付

- 本地账号按患者、医生区分角色。通过本机命令行显式建立开发账号，没有公共注册、角色提升或自动生成账号接口。
- 密码使用随机盐和scrypt保存；登录会话为随机令牌，数据库仅存令牌哈希。会话30分钟到期，退出立即失效；停用账号后原会话也无法继续访问。
- 连续5次登录失败后，对该用户名限制15分钟；未找到账号和密码错误均返回统一鉴权失败。该限制用于本地开发，不作为生产防护或容量承诺。
- 患者账号只能创建和查看自己的单个合成患者档案。医生只能看到有有效授权的患者，不能自行获得访问权、替患者授权或建立本人患者档案。
- 患者可查看本地可用医生账号，创建、查看与撤销自己的授权。开发授权默认60分钟，可设置1分钟至24小时；该时间范围不是医院正式授权政策。
- 每次患者资料读写均重新检查登录状态与当前授权。授权撤回或到期后，医生后续列表、历史读取与新增保存立即被拒绝；不存在和无权访问的患者统一返回404。
- 年龄、主诉、持续时间、相关病史、粘贴文本可作为快照保存。范围限定成人，接口必须明确声明 `synthetic_only=true`，拒绝额外身份、角色等字段。
- 资料每次保存生成新版本，不覆盖旧输入。采用预期版本号处理并发写入，冲突返回409；保存快照和对应操作事件在同一事务完成。
- 历史每页最多20条，返回下一页游标。患者/医生账号列表和授权列表各最多100条，尚未实现更大规模的列表分页。
- 保存的操作事件仅包含动作、操作者ID、资源ID和时间，不存患者正文、密码或原始令牌。患者正文与知识资料库完全分离，不进入共享向量库。

这些是单一本地开发环境中的账号与授权规则，不能替代医院身份核验、机构隔离、正式患者绑定或授权办理流程。`synthetic_only`是调用方的开发声明，不会自动识别正文是否误含真实信息；当前仅允许输入虚构资料。

## 存储及接口

首次显式使用业务接口或账号建立工具时，初始化 `var/business-synthetic.sqlite3`。采用独立SQLite开发存储，表包括账号、会话、失败登录计数、合成患者、授权、不可覆盖的资料快照和操作事件；数据库版本为1。未改动原知识治理库和审核库。

接口前缀 `/api/v1/business`，登录仍需工作台本机会话及同源POST检查；其余业务资源额外要求独立业务登录Cookie。业务Cookie仅用于该前缀、HttpOnly、SameSite=Strict。本地HTTP入口不能直接用于医院部署。

| 方法与路径 | 用途 |
|---|---|
| `POST /login`、`POST /logout`、`GET /me` | 登录、退出、身份与角色 |
| `GET /patients`、`POST /patients` | 获准访问的患者列表、创建本人合成档案 |
| `POST /patients/{patient}/snapshots` | 保存新资料版本，提供 `expected_revision` |
| `GET /patients/{patient}/snapshots?before=…` | 分页查看获准访问的资料历史 |
| `GET /doctors` | 患者选择可用的本地开发医生账号 |
| `GET /patients/{patient}/grants`、`POST /patients/{patient}/grants` | 患者查看及创建本人授权 |
| `POST /patients/{patient}/grants/{identity}/revoke` | 撤销本人授权 |

后续开发人员可使用以下本机工具建立虚构账号，密码在终端隐藏输入，不通过命令参数或聊天提供。本轮未实际执行账号创建。

```powershell
.venv/Scripts/python.exe scripts/create_business_account.py synthetic-patient --role patient
.venv/Scripts/python.exe scripts/create_business_account.py synthetic-doctor --role doctor
```

账号密码长度12至200字符，无默认密码。患者档案与授权仍需后续通过业务接口建立，不会因为创建账号自动登记患者信息。
