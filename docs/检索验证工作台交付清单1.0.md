日期：2026-10-19。状态：本地页面、真实检索API、审核标记和浏览器验收完成。

## 打开与启动

当前入口：<http://127.0.0.1:8010/>。服务已启动；停止后可在项目根目录执行：

```powershell
.\scripts\start_validation.ps1
```

脚本只监听127.0.0.1，默认8010端口，关闭访问日志与LangSmith追踪。另开窗口运行时可以Ctrl+C停止。原M0的8000端口、配置和合成API保持独立。

先点“填入示例”，可修改信息再检索；默认只做混合检索，勾选“对比重排序结果”才额外运行重排序。

## 页面与流程

- 输入成人年龄、主诉、持续时间、相关病史、补充记录和咨询问题。年龄18–130岁，字段分别限制长度，合并查询超过500字符时明确报错，不静默截断。
- LangGraph分为患者信息整理、候选检索、可选重排序三步。使用现有802个开发片段与真实本地模型，不生成诊断或治疗解释。
- 同一候选池展示原混合前10与重排前10，显示运行快照和处理耗时。
- 可展开完整原文、版本ID、片段ID、字符偏移、原文定位与来源链接。重排分数明确不等于医学可信度。
- 每条可标记“相关／不相关／证据不足”，保存后显示确认；同一运行和同一片段重新标记会更新该条记录。
- 清空会移除当前页面输入和结果；查询中清空后，旧响应不会重新填回结果。
- 对原文中明确的18岁以下年龄范围增加人群复核提示。该提示只是辅助筛查，不能证明其他片段均适用于成人，也不修改原资料或原实验标签。

## API

| 路由 | 用途 |
| --- | --- |
| GET `/` | 页面及本地会话cookie |
| GET `/api/v1/validation/status` | 资料快照、片段数、模型可用状态 |
| POST `/api/v1/validation/retrieve` | 患者信息与问题检索，可选择重排对照 |
| POST `/api/v1/validation/reviews` | 保存当前运行内资料的相关性标记 |

POST需页面签发的HttpOnly/SameSite cookie及同源Origin；不允许跨来源写入。服务限制回环连接，错误响应不回显输入。它是本机开发会话，尚不是医院身份认证、医生授权或患者账户系统。

检索请求字段：age、chief_complaint、duration、history、pasted_text、question、compare_reranker。审核请求字段：run_id、strategy（hybrid/reranked）、version_id、chunk_id、judgment（relevant/irrelevant/insufficient）。

## 输入与审核数据

患者输入只用于当前请求，应用不写入患者数据库或查询历史，也不放入页面localStorage。E5与重排子进程通信改为stdin/stdout内存管道，不再产生含查询的临时request.json。这里说明应用的数据处理方式，不承诺操作系统交换文件、浏览器外部工具等系统级行为。

审核SQLite位于 `var/validation-feedback.sqlite3`，仅存run_id、snapshot_id、strategy、version_id、chunk_id、judgment、updated_at，没有问题、年龄、主诉、病史、粘贴记录或自由文本字段。

可审核运行仅在内存保留公开资料身份，最多50次、有效30分钟；重启后需重新检索才可提交新标记。已保存审核记录保留。因为不保留问题和患者输入，这些记录不能独立还原咨询场景，也不能直接转换为问答金标准。相关性反馈不自动批准资料、不发布标签、不调整默认配置。

模型执行串行，重复并发检索返回“当前有检索任务”；这是CPU开发工作台，尚未做医院并发负载与账号权限验收。

## 通信改造与版本追踪

通信方式改造会改变模型工作进程代码哈希，因此E5组件指纹更新并重建索引。旧索引保存在 `knowledge/index-archives/before-stdio-e5.json`，配置、模型权重、资料快照和融合参数不变。

对802条新旧向量逐项比较，最大差异0；按原实验第一批输入核对8组重排得分，最大差异0。记录在 `evaluations/reports/workbench-1.0/transport-parity.json`。旧评测报告继续保留原指纹，不覆写为新组件版本。
