# 咨询后台任务与失败恢复交付清单2.0

日期：2026-10-20。

本轮按确认的方案实现后台任务：失败、超时或中断后由用户明确确认重试，不自动重新运行可能已经产生费用的请求。页面仍为 http://127.0.0.1:8011/patients ，当前8011已加载新接口和执行器，刷新页面即可使用。

## 已交付

- 提交接口改为HTTP 202，先持久保存任务再返回。页面不再等待完整生成结束，可以继续操作或离开，任务由服务器执行。
- 持久记录排队、执行、完成、失败及中断。阶段显示排队、访问检查、检索/生成/证据验证等实际状态，不显示虚构百分比。
- 页面自动查询当前任务，通常每2秒一次；状态查询失败逐步退让，最长间隔15秒。页面隐藏时暂停查询，服务器仍执行；刷新回来可继续查看最近的待完成任务。
- 相同账号、患者与提交编号重放仍返回原任务，不创建第二次生成。自动查询、历史读取和刷新均不调用生成器。
- 已失败、超时或中断的任务不自动重排。重试按钮先提示可能重复计费，再要求重新核对资料与发送同意，使用新编号建立新任务，保留原记录。
- 回答流程虽已结束但输出未通过校验时，仍不展示草稿，也不自动重试；页面提供同样的人工准备重试入口。
- 未开始的排队任务在服务恢复后继续等待执行，但发起账号、原会话或授权已经失效时，任务直接失败，不发送模型请求。
- 已开始但因服务停止或执行权失效而无法确认结果的任务，标记中断，不自动重跑。数据库版本2遗留的未知运行中记录也按中断处理，保留原完成记录。
- 执行器使用数据库租约与心跳，同一库仅允许一个有效执行器正常领取任务。旧执行器失去租约或停机后，迟到结果不能覆盖中断、失败或完成状态。
- 每次开始执行及保存结果前，重新检查原会话、账号和患者访问授权；后台仅保存会话令牌的哈希引用，不保存明文令牌或密码。
- 停机先阻止继续领取任务并标记已开始任务；模型客户端在生成线程退出后再关闭，避免在进行中的请求里提前关闭客户端。
- 切换患者、退出或登录失效会清除轮询。旧查询即使随后返回，也不会重新显示原患者的输入、答案或历史。

## 恢复与超时规则

当前本地实现为单库、单有效执行器、串行咨询任务；不改变现有LangGraph的引用校验与限次修订流程。

- 租约默认15秒，每约1秒心跳。硬中断后，新执行器需等旧租约过期才能接管；已开始的任务转为中断，未开始任务才可继续。
- 默认任务监测上限15分钟，从开始阶段计算，不含排队时间。达到上限后记录超时，停止接受该任务的迟到结果；供应商请求超时也可归类为超时失败。
- 业务库临时不可用时无法立即落状态，执行器恢复后依租约检查处理未确认任务；不据此保证故障发生瞬间即可完成状态更新。
- 底层线程或已发送的供应商请求不能可靠强制取消。超时/停机标记阻止结果回写，但不撤销供应商费用；若底层调用仍未返回，当前进程的后续处理可能继续等待它结束。
- 现有RAG内部已有限次格式修订、证据核验和连接重试仍保留；本轮禁止的是调度器自动重新执行一条已失败或中断的咨询，不是把单条RAG流程限制为一次模型请求。
- 服务恢复不延长登录或患者授权。排队期间会话过期或退出后，需有权账号重新确认发送。

这仍是本地开发实现，不是分布式生产任务平台，也不开放真实患者信息。

## 数据库与接口

业务数据库升级为版本3，新增 `consultation_jobs` 和 `consultation_worker`，保留账号、授权、资料与完成的咨询。内部咨询表沿用既有终态约束，API结合任务表返回更完整的状态；客户端无需理解内部表结构。

接口仍为 `/api/v1/business/patients/{patient}/consultations`：POST接收后返回202及任务ID，GET列表和GET详情只读取当前状态或结果。直接同步适配器保留给现有隔离测试/工具；用户页面和HTTP提交均走后台队列。

## 验证

- 新增14项队列测试；完整离线回归386项通过，Ruff与页面JavaScript语法检查通过。另针对停机客户端关闭顺序及旧状态迁移补测通过。
- 故障测试覆盖持久排队、会话哈希、幂等重放、单有效执行器、心跳续约、租约接管、停机、中断后迟到结果拦截、超时、撤权/退出/到期、失败不自动重试、数据库升级以及实际FastAPI生命周期重建。
- 12项新浏览器检查通过：202快速返回、串行排队、刷新恢复、自动更新、历史无模型调用、丢失响应重放、失败等待人工、取消重试、重新同意后单次运行、校验拒答不自动重试、退出后迟到响应隔离、手机布局及无脚本错误。
- 原患者页面17项浏览器回归通过。实际8011登录页另外只读检查，无POST；202响应、数据库版本3和执行器有效心跳已核对。
- 一例独立存储的真实RAG后台检查，从 `queued` 进入 `completed`，单次工作流、实际供应商POST 4次，重复提交没有重新执行，授权医生读取同一结果。该次已有开发样例 `GEN-ENT-002` 的模型输出为 `validation_failed`，系统正确保存拦截状态，未展示原始草稿，也未自动重试。
- 上述真实检查证明后台运行与结果拦截路径，不代表回答质量通过；不作为新独立评测或医学验收。4次POST属于原有单次生成/核验/修订流程，不是4次后台任务重跑。
- 实际工作台未新增账号、患者或咨询任务；真实候选审核记录仍为0，原知识快照及802个片段不变。新增执行器租约和心跳属于任务基础设施状态，不是患者业务记录。
