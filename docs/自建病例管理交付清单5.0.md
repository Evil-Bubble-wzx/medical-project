# 自建病例管理交付清单5.0

日期：2026-10-22。全局清单编号由4.9推进到5.0，不重置阶段编号。本轮让本机工作台能管理普通自建合成病例，保留6个预置体验病例。

## 已完成

- 医生登录后可新建合成病例，再填写年龄、主诉等信息并保存第一版资料；新病例不会沿用上一病例的输入或咨询版本。
- 新建请求带稳定编号，重复提交返回同一病例；同一编号对应不同名称时拒绝，不重复建立病例。
- 新病例只由创建医生管理，不生成可登录的患者账号，不需要重复授权。底层保留一个禁用登录的合成归属记录以兼容现有患者资料外键；它不代表真实患者同意。
- 支持病例名称搜索、重命名、归档和恢复。名称/归档状态具有独立版本，冲突不覆盖；重新载入会取得最新管理版本。
- 归档保留资料版本、咨询结果与引用，仍能查看历史，不能新增资料或提交新咨询。已排队但未开始的任务在归档后不调用模型；已经开始的生成可能完成并作为历史保留。
- 归档列表支持打开旧病例查看历史或恢复。仅自建病例可管理名称与归档，原6个预置病例及别人授权的患者不开放此管理权限。
- 用户界面继续使用原患者资料、后台咨询和历史组件，没有新建另一套回答流程。自建病例不会因名称恰好与预置病例相同而自动套用示例问题。

## 现在如何使用

1. 打开 http://127.0.0.1:8012/doctor ，登录现有账号。
2. 左侧“新建合成病例”填名称，确认虚构信息，点击新建。
3. 右侧填写年龄、主诉、病程等，保存资料后填写问题并确认发送。等待咨询完成，展开引用或回看历史。
4. 名称与归档按钮在当前自建病例标题下。归档病例从左侧“已归档病例”读取，打开后可查看历史并恢复。

当前每个开发医生最多保留80个自建病例（含归档）；创建者持续管理，不依赖预置病例24小时授权。没有转交、分享自建病例或永久删除功能。当前共享开发账号不等于医院医生身份，仍仅用于本机合成信息。医学审签与真实患者使用政策不阻塞本轮程序开发，但也没有因此完成。

升级后的schema 4数据库不能直接交给仅支持schema 3的旧代码；若回退旧版本，请停机并按恢复说明使用升级前备份。本轮未提交或推送GitHub。
