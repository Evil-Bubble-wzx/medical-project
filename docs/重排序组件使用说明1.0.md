# 重排序组件使用说明1.0

重排序是可选的第二阶段排序，不修改资料、初始候选生成或默认配置。

## 本地使用

在项目根目录PowerShell中：

```powershell
.\scripts\retrieval.ps1 search --mode hybrid --rerank --query "成人鼻炎患者的共病资料有哪些？"
```

省略 `--rerank` 仍走原混合检索。该标记仅适用于 `search --mode hybrid`，原benchmark不因安装模型而自动启用重排；对照实验使用 `scripts/experiment_reranker.py`。

首次准备模型可运行 `.venv\Scripts\python.exe scripts/download_reranker_model.py`。下载器从官方仓库固定提交、核对Apache-2.0声明，并对权重校验上游哈希；模型存于 `models/mmarco-minilm-reranker`。本轮使用量化ONNX与现有CPU运行时，不需新增模型API密钥。

## 接口与处理

- `PairScorer.score_pairs(pairs)` 接受问题和段落对，返回同序有限实数分数。替换模型只需实现此接口及自身指纹，不得改变证据身份或自行添加段落。
- `LocalCrossEncoder` 使用独立本地Python子进程，载入已校验的ONNX与tokenizer，不执行远程模型代码。推理依赖路径沿用 `configs/retrieval.json` 的 `embedding_python`，迁移机器时需调整。
- 固定输入为问题与“标题＋小节＋正文”，不添加E5的query/passage前缀。最大512 token，截断文档侧，按单一原始logit降序排列，保持稳定证据ID作为同分排序依据。
- `RerankedRetriever` 默认取原混合检索最多40个候选，重排后返回前10。重排结束后重新检查固定资料快照的可用性，过滤已撤回内容；可通过现有LangGraph检索工作流调用。

分数是当前模型的排序值，不是医学正确率或经过校准的相关概率。没有设置自动拒答阈值；边界行为仍待单独评测。单次CLI查询会额外启动模型进程，批量实验均摊耗时不能当作该命令的单次延迟。

## 模型适用性

模型为 [cross-encoder/mmarco-mMiniLMv2-L12-H384-v1](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1)，官方卡声明Apache-2.0许可，语言含中文和英文。其mMARCO训练资料不是医学专项数据；支持两种语言并不保证中文问题与英文医学段落匹配良好，是否采用以当前项目实际评测和后续审核为依据。

实验固定原50道开发题、原标签与资料快照，新增36题不参与。结果文件另存目录，默认配置不自动变更。重新运行时需使用新输出目录，保留旧报告和模型指纹。
