## 2. 可运行流程

```text
查询与合成患者信息
  → 准备查询
  → 按已发布状态、知识范围和快照过滤检索
  → 重排
  → 合成证据策略
      ├─ 缺信息 → 追问结果
      ├─ 无证据 → 依据不足结果
      └─ 有证据/预设冲突 → 生成专业部分、患者摘要及引用
          → 验证引用和抽取正文
          → 不通过时最多修订一次
          → 仍不通过则返回依据不足结果
  → 输出结构化答案与运行清单
```

检索器和生成器可分别通过配置切换，无需修改图拓扑或 API。`configs/local.toml` 为默认实现；`configs/alternative.toml` 为反向排序检索器与简洁生成器组合。自动化测试验证实现确实不同、排序/表达发生变化、图结构保持一致。

## 4. 运行与复核

在 `C:\medical-project` 中运行：

```powershell
# 新环境首次安装需要网络；现有环境已经安装完成
.\scripts\setup.ps1

# 一条命令检查 M0
.\scripts\verify.ps1

# 启动本机 API；终端保持运行，Ctrl+C 停止
.\scripts\start.ps1

# 单独评测替代组件，自动新建报告目录
.\scripts\evaluate.ps1 -Config configs/alternative.toml

# 临时启动 API、发送真实 HTTP 请求、自动关闭进程
.\.venv\Scripts\python.exe scripts/smoke_api.py
```

API：`GET /health`、`POST /api/v1/demo/query`，接口文档位于本机 `/docs`。启动脚本绑定 `127.0.0.1`，生成本次随机演示令牌；请求示例和四种分支输入见 [README](../README.md)。

Windows asyncio 创建事件循环需要本机回环连接。此次验证是在允许回环的执行环境完成；限制回环的沙箱内会在事件循环创建阶段阻塞，必须在正常本机终端运行。测试额外阻止了外部网络连接；运行无需模型密钥。

## 5. 已知边界

- 当前无真实模型调用、Embedding 或向量检索，未启用云端追踪。所有知识内容均为合成工程条目。
- Fake 冲突策略使用样例预置标签，主诉/持续时间追问也是工程规则，不是医学规则。
- 验证器可检查合成抽取答案和引用定位，不是通用医学语义判断模型；患者摘要的通用语义评测需后续实现。
- Parser/Chunker/Embedder/VectorIndex 等已定义接口，尚无真实入库实现。
- 当前未保存患者信息，未实现数据库、checkpoint、登录、医生授权、资料审核发布和前端页面。这些属于 M1—M3。
- 演示令牌和知识范围过滤不等于正式医院身份与患者权限体系；仅接受合成信息，不接真实患者数据。
- 版本锁定已实现，发行包哈希锁与其他操作系统未验证；本阶段使用源码目录运行。
- 院方正式验收、容量、备份恢复、部署及真实数据边界仍按开发文档保留待定。
