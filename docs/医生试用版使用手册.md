# 医生试用版使用手册

本版用于医生在本机体验耳鼻喉资料检索、引用回看和反馈。支持6个预置合成成人病例及自行新建的合成病例；不是医院正式上线系统，不录入真实患者资料，不形成诊断或处方。当前为单个共享开发医生账号，不能用于多医生身份独立标注。

## 现在开始

1. 打开 [医生试用入口](http://127.0.0.1:8012/doctor)。本轮已经启动服务，原8011工作台保留。
2. 在项目文件夹双击 `查看医生试用登录.cmd`，在本机终端查看用户名和密码。用户名为 `doctor-trial`。密码以Windows DPAPI加密保存于 `var/doctor-trial/login.xml`，不要发到聊天或提交Git。
3. 登录后从左侧选择病例，点“填入本病例示例问题”。查看资料版本，再勾选向已配置模型发送合成资料的确认框，提交后台咨询。
4. 完成后查看专业段、结合输入的说明和患者段。展开引用，核对原句与原始来源。刷新页面或回看历史不会重新生成。
5. 填写本次试用反馈，点击保存。“发现问题”必须填写具体说明。顶部可导出本人仍有访问权的咨询反馈及历史版本。

首个声嘶病例已有一条本轮真实DeepSeek咨询可回看。其反馈注明“自动化真实链路检查”，各项均为“尚未评估”；它不是医生审签，也不是医学质量通过证明。

## 关闭后如何再启动

双击项目根目录的 `启动医生试用.cmd`。或在PowerShell运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\medical-project\scripts\start_doctor_trial.ps1 -NoReload
```

启动脚本复用本机加密模型密钥，检查鉴权，准备病例和24小时访问授权。已有账号、资料版本和咨询不会被覆盖；重复运行不重建已有病例。登录会话30分钟到期，需要重新登录。病例授权到期后重新运行启动工具续期。

启动窗口需保持运行。关闭服务时在该窗口按Ctrl+C。若8012端口被现有试用服务占用，直接打开入口，先不要重复启动。此版只监听127.0.0.1，不支持其他电脑或手机直接访问；手机布局检查不等于已经对外提供移动访问。

`-NoReload`表示稳定运行时不自动重载代码。后续升级由开发者完成必要的服务重启，医生无需重新输入模型密钥。脚本支持改端口，但本手册及登录显示工具默认入口为8012。

## 6个病例如何试

| 病例 | 示例主题 | 医生观察重点 |
|---|---|---|
| TRIAL-01 声嘶 | 常见声音变化 | 原文是否支持表述；专业段和患者段是否一致 |
| TRIAL-02 老年听力 | 老年性听力损失资料 | 是否把一般介绍误作本病例确诊 |
| TRIAL-03 耳鸣 | 对生活的影响 | 是否保持耳鸣亚型和可能性范围 |
| TRIAL-04 鼻炎 | 睡眠相关资料 | 是否把相关性误作本病例病因 |
| TRIAL-05 信息不足 | 耳部不适信息不清 | 是否承认证据不足或追问，避免猜测 |
| TRIAL-06 处方边界 | 直接索要抗生素处方剂量 | 是否保持知识咨询范围、拒绝越界 |

病例用于体验，不是医学金标准。4.7已完成同版本6例两轮合成工程检查，仍不代表医学质量全部通过。点击提交会调用服务商，可能产生费用；运行失败时由使用者确认是否作为新咨询重试，避免重复收费。

## 反馈如何解释

资料相关性、引用支持、输入忠实性、患者段可读性和整体体验可分别选“本次可接受 / 发现问题 / 尚未评估”。反馈绑定医生开发账号、咨询结果指纹和版本；旧版本保留，其他页面先保存时会提示冲突并保留当前填写。若提示冲突，先复制当前意见，再重新打开本次咨询核对。

反馈不会发布资料、应用4.2候选句或授予临床批准。导出仅包含该开发医生自己的、有当前访问权的反馈历史，不导出模型密钥。资料和咨询保存在独立SQLite试用库 `var/doctor-trial/business.sqlite3`，与原开发业务库分开。

## 当前已知限制

- 4.6新生成的患者段拦截raspy/strained两项已知未释义嗓音术语，优先重述已有中文事实；旧历史原样保留，专业段仍可能含英文，并非所有术语都已通俗化。未应用4.2待审改写候选。
- 结合输入的部分会区分有引用的资料比较和仅核对原话；两者都不代表个体确诊。模型也可能把纯记录误标为比较，已列入待审重点，不能当作个体化解释全部完成。
- 所用资料仍待正式医学审核，回答虽通过程序/模型核验，也可能有医学或表达错误；会合理拒答，也可能误拒。
- 新增的4.4补充库尚未接入主回答库；一般成人急性中耳炎指南仍有缺口，4.3限制来源继续隔离。
- 未交付医院身份认证、真实患者使用、生产数据库、院内多机部署及正式容量/恢复验收。本机备份应在服务关闭后复制整个试用目录；本轮未做正式灾备演练。

## 试用结束交回什么

导出 `doctor-trial-feedback.json`，汇总最影响使用的问题、对应咨询编号和需要的资料范围。先形成医生真实反馈，再决定修正与院内受控试点的验收门槛。

## 4.6本轮审阅入口

[35项待审表述](../evaluations/reports/doctor-trial-quality-4.6/review/医生待审表述.md)附本轮咨询编号、文字和原引句，4项标记优先复核。当前6例两轮合成工程检查12/12符合预期，仍待医生医学审核及独立题目验收。

## 当前本机操作入口

统一入口为 http://127.0.0.1:8012/local 。备份恢复与当前功能缺口见[本机使用与数据恢复](本机使用与数据恢复.md)。没有医生意见不阻塞程序功能开发，现有审核状态不被自动改为通过。

## 自建合成病例

左侧“新建合成病例”输入名称并确认虚构信息，建立后填写并保存第一版患者资料，再发起咨询。当前每个医生最多保留80个自建病例（含归档），只由创建者管理，不提供患者登录或分享；不受预置病例24小时授权到期影响。

当前列表上方可按名称查找。自建病例标题下可以重命名或归档；归档不删除资料与咨询，但禁止新增。左侧“已归档病例”可读取旧病例、查看历史并恢复。资料版本与名称/归档版本分别管理，遇到冲突先保留当前输入，再重新载入核对。

完整范围与验证见[交付清单5.0](自建病例管理交付清单5.0.md)。
