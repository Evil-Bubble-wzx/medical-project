# 编号原文与逐项支持修复交付清单1.0

日期：2026-10-19。范围：闭环长引文测试，改进复合论断与引文覆盖，重跑12个固定模拟案例并开发复核。

## 已实现

- 新增服务端quote_catalog。为本次证据正文生成有编号、8至300字符的连续原文片段；超长完整段不截断充数，尝试按完整分号子段提供选项，仍超长则省略；已截断证据末尾的未完成片段不进入目录。规则分段不是医学句法解析，片段可能缺上下文，仍需核验。
- 新生成提示要求每项一句、单一可核验事实，明确列表数量上限，并优先选择evidence_id与quote_id。服务端按目录编号回填原文，禁止未知编号、错文档编号或同时提交quote/quote_id。原有字面quote兼容路径仍保留严格校验与限次修订，不自动放宽。
- 多个完整句子或分号拼在同一text时，返回non_atomic_claim并隐藏正文。没有用自动截断/删除任意句子来制造通过，语义原子性仍无法仅靠标点保证。
- answered核验只接收原始模拟输入和每条论断自己的supports.quote，不再提供整段正文替该项补齐引文。正向判定必须列出有效的本项引文下标，遗漏、重复、越界或不一致时失败拦截；拒答核验仍可使用本次完整证据包。
- 服务返回编号请求计数与核验记录，原临床审核标志始终false。新版本quote-selectors-1.0已由开发服务自动重载，无需用户重复输密钥。
- 评测脚本增补提示/配置哈希、分类状态及错误统计，并禁止不同提示或生成配置间复用结果。本地重载导致会话401时，只重新建立本地会话并重发尚未进入服务的请求；不会将其误报为供应商鉴权错误。

## 边界

编号回填只保证引用来自本次原文选项且长度受控，不保证其支持模型的全部结论。同模型第二次调用仍可能漏判，多句拦截也不意味着单句只有一个逻辑断言。仍需要逐条开发复核及上线前医学审核，尚未宣称医院上线验收通过。
