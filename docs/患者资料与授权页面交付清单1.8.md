# 患者资料与授权页面交付清单1.8

日期：2026-10-20。

本轮将1.7业务后端接到页面。地址为 http://127.0.0.1:8011/patients ，原检索首页与审核页均增加入口。当前服务已加载页面，刷新即可访问。

## 已交付

- 登录本地开发账号，显示账号及患者/医生角色，刷新后保留有效登录状态。密码提交结束即清空，不写入浏览器存储。
- 患者建立本人的合成档案；创建前须明确勾选虚构资料声明。医生不能建立患者所有权。
- 患者查看本人档案；医生只看到获得有效授权的患者，未获授权时显示空列表。
- 录入成人年龄、主诉、持续时间、相关病史及补充记录，明确勾选合成资料声明后保存为新版本。
- 重新载入当前资料时展示最新版本，合成声明重新保持未勾选，不自动代确认。
- 查看每个历史版本的完整字段与时间；每批20条，可继续加载更早版本，不覆盖当前表单。
- 患者选择本地医生账号及授权时长，确认后授权；查看授权记录、截止时间、有效/撤销/到期状态，并主动撤销。医生页面不显示授权管理入口。
- 资料尚未保存时，刷新、切换患者、重新载入及退出需要确认是否放弃。页面关闭或导航离开触发浏览器未保存提醒。
- 保存失败或并发版本冲突保留当前输入，明确提示先核对最新资料。重新载入由用户决定，不自动覆盖输入。
- 授权失效导致读取被拒绝时清除当前患者详情与缓存列表；退出或业务会话失效时清空页面中的患者资料并回到登录状态。已显示的资料不会因其他账号远程撤销而自动推送清除，下一次请求会重新校验并阻断。
- 动态档案名称、主诉及历史按纯文本显示。患者内容、密码和会话令牌均不写入localStorage或sessionStorage。

本页只处理虚构成人资料。保存不会调用模型，当前也不自动把已存资料填入问答工作台。医院账号、真实患者绑定、正式存储与上线能力尚未接入。

## 首次使用

实际工作台尚未创建开发账号。页面没有默认密码或自助注册，账号需通过本机工具显式建立。所有测试账号都在隔离的8012模拟服务，不适用于实际8011。

在项目目录的本机终端执行，按隐藏提示设置密码，不要把密码发到聊天中：

```powershell
.venv/Scripts/python.exe scripts/create_business_account.py synthetic-patient --role patient
.venv/Scripts/python.exe scripts/create_business_account.py synthetic-doctor --role doctor
```

随后用患者账号登录，建立虚构档案并录入资料；需要医生查看时，在“医生访问授权”中选择医生账号授权。医生在自己的浏览器登录后，点击“刷新身份与患者”即可看到获授权资料。

不同账号同时测试时应使用独立浏览器上下文，例如两个浏览器或普通窗口与隐私窗口。同一浏览器的普通标签页共享登录Cookie，不能视作两个独立账号会话。
