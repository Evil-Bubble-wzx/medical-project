# 审核记录存储与接口交付清单1.3

日期：2026-10-20。

本轮完成本地开发版审核后端：候选资料和题目查询、审核草稿保存、提交声明、历史追溯及审核表导出。可供下一步审核页面接入。

## 已实现

- 独立SQLite库：`var/candidate-reviews.sqlite3`，与检索反馈库、资料治理库分开。
- 草稿可不完整保存；提交时检查必填信息、来源依赖、证据身份及归档完整性。
- 每次保存新增历史事件，不通过接口覆盖或删除旧记录。历史保留当时的原始题目/资料及其绑定哈希。
- 修改需携带当前绑定哈希和版本号；旧版本或并发冲突返回409，避免互相覆盖。
- 原始候选包变化后启用新绑定，旧审核历史保留，旧版本记录不会自动用于新资料。
- 导出仅采用当前绑定中最新的已提交声明，草稿不计为已提交；来源重开草稿或排除后，关联题目的准入会重新计算。
- 提交失败事务回滚，不保留半条记录。每次数据库连接都在使用后关闭。
- 复用原有本地访问、会话Cookie与POST来源检查；接口不接受任意服务器文件路径。

## 接口

所有接口位于 `/api/v1/validation/audit`，使用当前工作台会话。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/items` | 列出资料与题目，可用 `kind=source` 或 `kind=case` 筛选 |
| GET | `/items/{kind}/{identity}` | 获取不可变原文依据、当前审核草稿/声明、绑定与版本 |
| POST | `/items/{kind}/{identity}/draft` | 保存审核草稿 |
| POST | `/items/{kind}/{identity}/submit` | 校验并保存审核声明 |
| GET | `/items/{kind}/{identity}/history` | 查看历史；支持 `limit` 和 `before` 分页 |
| GET | `/export` | 导出来源表、题目表及当前准入检查报告 |

写入请求包含 `binding_hash`、`expected_revision`、`review`；先从详情接口获取绑定和版本。具体审核字段沿用1.1、1.2的来源表与题目表；接口对字段类型、长度和额外字段另作严格检查。

状态含义：`pending`无记录，`draft`草稿，`submitted`已提交审核声明。`submitted`不等于医学审核通过或资料已发布。

## 开发版边界

当前是本地工作台后端，审核者姓名属于自行声明，尚无医院账号、角色或身份认证。响应中的 `clinical_approval`、`reviewer_identity_authenticated`、`eligible_for_formal_independent_scoring`始终为false。

数据库保存资料审核意见及其候选依据，不接收或持久化问诊接口中的患者输入。原文与候选题只读；审核提交不会自动激活资料、切换索引、授予治理库审核状态或发布到生产。

医学审核仍沿用上线前统一进行的安排。本轮存储中没有伪造任何医学审核人或已审核决定。SQLite事件通过本接口只追加，不代表具备防数据库管理员篡改的审计能力。
