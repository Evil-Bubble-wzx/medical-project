## 1. 代码交付

| 项目 | 改动 | 边界 |
|---|---|---|
| 输入绑定 | 非空输入按固定字段顺序提供 I1–I6 编号；模型只选编号，程序回填完整原话、字段、状态 | 不存在、重复、非字符串编号，以及同时提交编号和自定义原话均拒绝；状态仍是字段级词面标签，不是临床症状识别 |
| 原话记录 | 先回填、生成固定记录，再拆分医学论断；原话记录保留整段标点，不拆成重复记录 | 丢弃全部模型医学结论；明确声明 medical_comparison 的项目不得悄悄降级为原话记录 |
| 错误定位 | 原话记录先检查字段、完整引用与状态，再检查固定文本 | 旧归档未保存被拒草稿，不能倒推出旧样例具体哪个字段错了 |
| 摘要顺序 | 主生成可输出空摘要；内部临时副本只用于草稿结构校验；先核验专业及输入解释，再独立生成摘要，最后核验整份答案 | 专业核验不通过不生成摘要；摘要失败不展示临时副本；仍是模型核验，不能证明语义完全正确 |
| 摘要范围 | 独立摘要只接收保留的第一条专业事实、其引用及对应标题；标题只限定人群和疾病范围 | 未提供其他证据全文；实测仍出现引用支持、但超出专业段核心事实的扩写，尚未解决 |
| 资料撤回 | 专业核验及最终核验调用之后均重新检查资料准入 | 不能沿用核验前已撤回资料 |
| 核验诊断 | 格式错误保留有限字段位置和规则名，不保存原始草稿值、未知字段名 | 仅便于定位格式故障，不生成医学通过结论 |
| 失败提示 | 工作台、患者和医生页面区分输入绑定、模型格式、内容拒绝、核验失败及资料不可用；分类可保存回看 | 不改变原始 answered/validation_failed 等状态，不自动重新调用模型 |

主要代码：[input_fidelity.py](../backend/app/retrieval/input_fidelity.py)、[generation.py](../backend/app/retrieval/generation.py)、[answer_workflow.py](../backend/app/retrieval/answer_workflow.py)、[patient_summary.py](../backend/app/retrieval/patient_summary.py)、[verification.py](../backend/app/retrieval/verification.py)、[outcomes.py](../backend/app/retrieval/outcomes.py)。

新增专业核验步骤会增加模型调用；每个工作流仍只允许原有一次草稿修订，各核验步骤保留有限格式重试。26 是工作流样例数，不是供应商 API 请求次数。本轮没有准确统计供应商总请求次数，不将它写成 26 次。

## 4. 尚未完成及下一优先级

对全部 26 例归档输出的 AI 文本复核覆盖 47 个展示项：38 项有限支持、3 项需复核、6 项精确原话记录，实际医学文字项为 41，不能把 47 当医学论断通过数。3 项分别为 GEN-ENT-025/input_explanation:0 的过宽否定断言、GEN-ENT-036-CONTEXT/professional:0 的“或”关系歧义、BATCH-STATE-DENIED/patient_summary:0 的核心事实之外扩写。最后一项的原始引文支持新增内容，但仍违反摘要契约；不能混称为引文事实错误。

1. 摘要仍可能扩写引用中存在、但专业段没有选取的事实；“先核验再摘要”只解决顺序，未证明摘要严格收敛于核心事实。
2. “或”的中文枚举可能歧义、对资料缺失的否定断言可能过宽；通过同模型核验不等于充分依据。逐项 AI 开发复核及待审核标记见审核报告，不能当人工医学审签。
3. 诊断病程摘要及疾病范围仍有 5 例被挡；不能靠放松规则或反复调用刷成功，应继续定位草稿内容与误拒原因。
4. 仍缺合格医学审核、独立冻结标注集与泛化验收。真实患者、医院身份、生产数据库、容量和备份恢复不在本批完成范围。

后续优先收紧“摘要只保留核心事实”的生成及验证契约，并处理范围与否定断言。统一总表 F11、F12、F25 保持部分完成，**质量未通过**。
