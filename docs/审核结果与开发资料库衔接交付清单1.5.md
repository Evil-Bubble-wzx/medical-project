# 审核结果与开发资料库衔接交付清单1.5

日期：2026-10-20。

本轮完成审核后端与开发资料库的衔接。通过独立模拟资料验证纳入、索引、启用、撤回和回滚；真实6份候选来源、36道题目仍待审，没有自动纳入或发布。

## 已交付

- 选择证据题后生成纳入计划，检查该题与依赖来源的已提交“建议保留”声明、完整字段及原始归档指纹。其他待审题目不被顺带纳入；边界题不能作为资料纳入入口。
- 计划绑定候选集、来源清单、审核记录版本、审核内容指纹以及当前开发快照。意见或资料版本发生变化，旧计划不能继续使用。
- 只复制所选题目绑定的证据片段进入开发版本，保留原文定位与原始归档。相同来源以本次选择的片段范围替换该来源当前开发版本，不自动合并此前全部片段。
- 准备与启用分开：先创建不活动的快照及其独立向量索引，构建完成后再明确启用。准备失败或启用冲突时保留原活动快照。
- 启用同时校验索引文件、语料指纹、编码器身份、审核绑定及预期活动快照，事务内切换开发指针。既有检索器会在下一次向量检索时加载新快照索引，无需重新输入API密钥。
- 审核重开为草稿、重新提交形成新修订，或候选集/清单发生变化时，旧绑定版本停止参加关键词与向量检索。需要重新准备、明确启用新版本。
- 开发撤回在索引构建前提交停用状态；即使随后索引失败，被撤回版本仍不可检索。历史引用保留用于追溯，回滚不能恢复已撤回或审核绑定过期的版本。
- 回滚先从历史开发快照准备一个新快照及索引，再明确启用，保留原始历史记录。

提交声明仍不等于医学批准。新纳入版本保持 `draft`、`clinical_review=pending`、`production_eligible=false`；本流程不创建医学批准记录，不切换正式快照，不开启正式独立评分。

## 后端接口

接口共用工作台本机会话及同源检查，前缀 `/api/v1/validation/development`。

| 方法与路径 | 用途 |
|---|---|
| `POST /plan` | 输入 `case_ids`，只读生成计划；返回 `plan_id`、基础快照与审核绑定 |
| `POST /prepare` | `operation=include` 时输入题目和计划；`rollback` 时输入历史快照；`withdraw` 时输入开发版本 |
| `POST /activate` | 输入准备完成的快照、预期当前快照、操作者和原因，明确启用 |
| `GET /history` | 查看当前活动开发快照及最近100个准备记录 |

写操作必须提供操作者与原因，并明确传入预期当前快照（首次为空）。服务不接受客户端指定正式渠道、数据库位置或索引输出位置。操作者为本地声明标签，尚不构成医院账号身份认证。

本轮交付的是后端流程和接口；现有 `/audit` 表单继续用于填写审核意见，尚未增加这些开发版本操作按钮。后续页面可直接接本轮接口。
