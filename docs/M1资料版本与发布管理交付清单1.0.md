# M1 资料版本与发布管理交付清单 1.0

日期：2026-10-19（Asia/Shanghai）。范围：资料登记、审核/发布/撤回、检索快照及历史追溯。

本轮实现 M1 的资料管理闭环，以命令行交付。没有执行真实临床审核；现有 12 份资料均登记为 draft（待审核），3 条仅题录资料单独登记且不进入全文检索。

## 交付内容

| 功能 | 实现与约束 |
| --- | --- |
| 持久化登记 | 独立 `knowledge/governance.sqlite3`，schema v1；资料身份、原始元数据、内容指纹、导入时间、段落均保存 |
| 不可变版本 | 原文、分块或重要元数据变化创建新版本；抓取时间变化不创建版本；重复导入不重置审核、不复活撤回、不把最新版本指针退回旧版本 |
| 审核 | draft → reviewed；必须记录审核者及临床、许可、成人适用性、现行版本四项确认与依据；可指定通过的文本块 |
| 发布 | reviewed → published；同一事务写入发布状态、正式快照、活动指针和操作事件 |
| 撤回 | 任意非撤回状态 → withdrawn；撤回后终止新检索使用，旧快照也不能重新检索到该版本 |
| 开发检索 | 可使用待审版本，仅返回成人开发候选块；不表示已批准用于正式回答 |
| 正式检索 | 默认使用 production 通道，仅返回当前快照中已发布且审核通过的块；未发布时返回空结果 |
| 快照回滚 | 可激活历史有效快照；生成新激活记录，不改写旧快照；含撤回版本的快照禁止恢复 |
| 历史引用 | 通过 snapshot_id、version_id、chunk_id 回溯原文、位置和当时元数据；明确显示当前是否撤回，仅供本地审计 |
| 操作记录 | 登记、审核、发布、撤回和快照切换记录 actor、原因、时间及相关版本 |
| 兼容旧入口 | `library.ps1 search` 在管理库存在时转到受状态约束的开发检索，不能通过旧入口找回已撤回版本 |
| 采集衔接 | 重新采集后若管理库存在，自动登记新版本；不会自动审核或发布 |

## 文件

- `backend/app/knowledge/governance.py`：事务、版本与快照、状态及检索规则。
- `backend/app/knowledge/governance_schema.sql`：SQLite schema v1 初始化迁移。
- `backend/app/knowledge/manage.py`：管理 CLI。
- `scripts/manage_knowledge.ps1`：PowerShell 入口。
- `scripts/check_governance.py`：实际资料管理库的只读一致性验证。
- `backend/tests/test_governance.py`：状态隔离、发布/撤回、并发、失败回滚及版本追溯测试。
- `docs/review-attestation.template.json`：默认全部未确认的审核模板，不能直接提交为通过。
- `knowledge/governance-verification.json`：本次本地管理库验证报告。

## 使用

所有命令从 `C:\medical-project` 执行，默认管理现有本地库：

```powershell
# 看当前版本状态及通道快照
.\scripts\manage_knowledge.ps1 status

# 同步现有资料；重复执行不会产生重复版本
.\scripts\manage_knowledge.ps1 sync --actor local-developer --note 'Register local sources'

# 查看各资料的版本ID、快照和操作历史
.\scripts\manage_knowledge.ps1 history
.\scripts\manage_knowledge.ps1 history --document tinnitus-s3-2022

# 待审核资料仅用于开发检索
.\scripts\manage_knowledge.ps1 search '耳鸣' --channel development --limit 3

# 默认正式检索；当前尚未审核发布，因此应为空
.\scripts\manage_knowledge.ps1 search '耳鸣'

# 本地管理库一致性验证；不执行任何临床审核
.\.venv\Scripts\python.exe scripts/check_governance.py
```

后续真实审核完成后，审核人应另存并填写审核 JSON。四项确认必须为 true，并提供至少10字符的依据。`approved_chunk_ids` 显式列出审核通过的块；若省略该字段，选择该版本的全部成人开发候选块，不含隔离块。混合人群资料只能通过显式选择已审核的成人块后发布。

以下命令中的尖括号是占位符，不可原样执行；当前不需要执行审核或发布：

```powershell
.\scripts\manage_knowledge.ps1 review '<version_id>' --actor '<真实审核者>' --evidence-file '<已填写审核文件.json>'
.\scripts\manage_knowledge.ps1 publish '<version_id>' --actor '<发布者>' --note '<发布依据>'
.\scripts\manage_knowledge.ps1 withdraw '<version_id>' --actor '<操作人>' --note '<撤回原因>'
.\scripts\manage_knowledge.ps1 activate '<历史snapshot_id>' --actor '<操作人>' --note '<回滚原因>'
.\scripts\manage_knowledge.ps1 citation '<snapshot_id>' '<version_id>' '<chunk_id>'
```


测试覆盖：待审隔离、审核后未发布隔离、批准块子集、四项审核要求、撤回对新旧快照及旧检索入口生效、重复导入不复活、版本替换/回滚、引用归属、文件损坏、事务失败回滚、并发发布只成功一次、批量导入全有或全无、局部审核不冒充整篇通过、未知 schema 拒绝。

真实资料只做登记和读取验证，未被测试流程审核或发布。测试中的通过确认均用于临时目录内的合成文档。

当前是 SQLite 本地可信操作员工具：actor 是人工填写的操作标签，不是经过认证的用户身份；操作记录可追溯，但不是防篡改签名审计。它没有提供医院多用户授权、网络管理 API 或可视化后台。后续接入正式账号权限后才能开放远程操作。

SQLite 发布状态、快照成员和活动指针采用同一事务切换；FTS 数据在版本登记时建立，查询根据快照及最新撤回状态筛选。没有引入外部缓存。历史快照成员保留不变，但撤回状态始终优先，不保证撤回后的旧实验仍能作为新查询重跑。

存储选择沿用现有 SQLite，不将 PostgreSQL 技能误用为已完成 PostgreSQL 部署。今后迁移 PostgreSQL 时需要独立的 schema、迁移及并发验证；本次无新增第三方依赖。

本轮不包含 PDF/Markdown/TXT 新上传解析、真实 Embedding/向量索引、生成模型接入或完整 M1 验收。下一步继续完善资料入库适配器与问题—证据评测集，再接真实检索。

事务与 FTS 实现参考：[SQLite transactions](https://www.sqlite.org/lang_transaction.html)、[SQLite FTS5](https://www.sqlite.org/fts5.html)。
