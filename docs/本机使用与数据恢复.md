# 本机使用与数据恢复

当前使用范围：本机合成信息开发使用，不要求医生意见才能继续开发；正式临床使用仍待医学与院方验收。

## 每次启动

1. 双击根目录“启动医生试用.cmd”，保留服务窗口。已有加密密钥时自动读取。
2. 双击“打开本机工作台.cmd”，或打开 http://127.0.0.1:8012/local 。此快捷方式只打开页面，不重复启动服务。
3. 选择“完整咨询工作台”，账号为 doctor-trial；双击“查看医生试用登录.cmd”在本机查看密码。
4. 选择合成病例，修改信息后保存新版本，填写问题、确认发送，再提交。完成后查看专业段、输入解释、患者段及引用；历史在当前病例下查询。
5. 退出时在服务窗口按 Ctrl+C。正常退出不清除数据库或加密密钥。

若页面打不开，先看服务窗口是否仍在运行。端口被占用时不要连续启动多个副本。查看登录密码的窗口只供本人使用，不要截图上传。

## 资料如何使用

已收集网上资料可供检索。/audit 支持查看来源、填写意见及开发版本的准备、启用、撤回。只为开发继续运行，不需要虚构医学审核通过。

现有网上资料采集命令（从项目根目录执行）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/library.ps1 -Action status
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/library.ps1 -Action search -Query "耳鸣"
```

直接导入可打开 http://127.0.0.1:8012/imports ：

1. 选择文字版PDF、DOCX、UTF-8 TXT/Markdown文件，或粘贴30—30000字原文；填写标题、原始来源链接、主题、许可依据、操作人及原因。
2. PDF/DOCX会先在本机提取只读预览，PDF按页、Word按段落/单元格定位；先核对提取顺序、缺失和表格，再确认。核对成人范围和文字复用许可，确认仅供开发。这里是操作人声明，不是系统自动鉴定，也不是医学审签。
3. 点击“保存原文并准备索引”。这一步保存不可变原文并建立新快照索引，当前问答库不切换。CPU建索引可能需要几分钟，不要重复提交。
4. 准备成功后点击“启用已准备资料”。之后的新咨询可以检索该资料；旧答案、快照和引用保留。
5. 在 /audit 的开发资料版本区域查看准备记录、撤回资料或回滚版本。撤回会立即让该版本不再进入检索，即使后续索引失败也保持撤回生效。

索引失败或版本冲突不会切换当前问答库。修改导入表单后必须重新准备。准备记录可以在版本管理查看，但离开导入页面后重新选择启用需到版本管理操作。重复手动准备会建立新的独立记录，不覆盖旧资料。

支持8MB以内文字版PDF和DOCX；PDF最多100页，提取文字最多15万字。无文字页、嵌套表格、超限、加密或损坏文件不能直接入库；扫描件需先OCR，旧版.doc不支持。Word图片、页眉页脚、脚注、批注、文本框不提取，表格按单元格线性提取。新URL只作为来源记录，页面不会抓取该URL。原文导入不会翻译、判断医学正确性或自动检查所有许可和成人适用范围。不要手改已归档正文和引文哈希。

原有网上来源批量采集仍由 knowledge/sources.json 和 scripts/library.ps1 管理；collect 会联网更新资料，不等于自动更新当前问答快照。

## 备份

双击“备份本机数据.cmd”，或运行：

```powershell
.venv\Scripts\python.exe scripts/local_data.py backup
```

输出备份目录位于 var/local-backups/时间-随机编号；保留整个目录。包含 knowledge、configs、本机试用库与加密凭据、开发业务/审核数据库。不包含代码、Python环境、模型权重、测试夹具。源码仍需单独保存，重新安装参照GitHub恢复说明。

SQLite使用备份API逐库快照并检查完整性。运行中备份不保证不同数据库的同一事务时点；需要完整停机一致性时先停止所有本项目服务，再执行备份。备份校验只检测文件损坏，不防止他人同时篡改文件与清单。备份含咨询历史和加密凭据，不要上传公开仓库；凭据仍受原Windows用户绑定。

## 校验与恢复演练

将下面路径替换为备份命令实际输出的目录：

```powershell
.venv\Scripts\python.exe scripts/local_data.py verify "C:\medical-project\var\local-backups\备份目录"
.venv\Scripts\python.exe scripts/local_data.py restore "C:\medical-project\var\local-backups\备份目录" --target "C:\medical-project\var\recovered-data"
```

目标目录必须不存在。恢复先验证清单、路径、每个文件大小及SHA-256，再复制并重新校验。不会覆盖活动项目，不会启动服务，也不会自动改变当前资料快照。

需要用恢复数据替换活动数据时：停止所有本项目服务，先为当前数据做一份备份；将当前 knowledge、configs、var/doctor-trial、var/secrets 及清单中的4个 var 数据库改名保留，再把恢复目录中的对应内容放回相同位置。数据库的旧 -wal/-shm 文件必须与旧数据库一起保留，不能与恢复数据库混用。确认后重新启动并检查患者历史与引用。此步骤为人工切换，当前没有一键覆盖恢复功能。

文件导入详细范围见[交付清单4.9](PDF与Word导入交付清单4.9.md)。预览24小时内有效，过期需重新解析。原文件在准备阶段复制到knowledge/local_text并纳入现有备份；未准备的临时预览保存在var/import-previews，不属于活动资料备份范围。

自建病例的名称、归档状态及禁用登录的合成归属记录保存在同一个试用业务库，随现有备份一起保存。操作见[交付清单5.0](自建病例管理交付清单5.0.md)。业务库升级为schema 4，旧版代码回退需使用升级前数据备份。

## 模型设置

http://127.0.0.1:8012/settings 支持调整当前DeepSeek官方模型ID、启用开关、单次超时和输出上限。先等待当前咨询结束，修改后保存，新请求读取新参数，无需重启当前服务。检查连接只请求模型列表，不发送患者信息。其他共用目录的服务应先停止，避免即时请求受到影响。

旧配置保存在var/settings-history，并随备份保存。当前页不修改API密钥，更换密钥使用 scripts/start_doctor_trial.ps1 -PromptForKey -NoReload 启动流程。详细说明见[交付清单5.1](本机模型设置交付清单5.1.md)。
