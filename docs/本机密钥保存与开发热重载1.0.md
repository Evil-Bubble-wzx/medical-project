# 本机密钥保存与开发热重载1.0

日期：2026-10-19。此前启动脚本仅将密钥保存在服务环境变量中；用户明确要求减少重复输入后，增加以下本机开发功能。

- 首次输入或更换密钥时，使用隐藏输入；通过官方API的GET /models进行不带患者信息的鉴权检查。401或检查失败时不写入缓存，也不启动新服务。
- 验证成功后，使用Windows SecureString的Export-Clixml保存到var/secrets/deepseek-api-key.xml。Windows DPAPI加密，仅同一Windows用户在同一电脑上可解密，不写明文.env；var/已被.gitignore排除。
- 后续启动优先读取加密缓存，不让终端中遗留的旧环境变量覆盖缓存。没有缓存时可读取已有环境变量或提示输入；-PromptForKey强制更换，并在验证成功后替换缓存。
- 密钥仅在本机脚本和服务进程中使用，不发到聊天，不打印密钥、代理信息或服务商响应正文。当前运行的旧进程密钥没有被提取，也没有声称已替用户保存了真实密钥；首次真实保存要通过新启动器完成。
- DeepSeek启动器默认启用后端Python代码自动重载，重载子进程继承启动器的密钥，不再反复提示。原始start_validation.ps1默认仍不重载；可用-Reload启用，DeepSeek启动器可用-NoReload关闭。
- 自动重载会重建开发服务和本地会话，页面提示会话失效时刷新页面；依赖/启动器等修改仍可能需要手动重启，但成功缓存的密钥无需重新输入。不是医院生产部署方式。

首次保存或以后更换密钥：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\medical-project\scripts\start_with_deepseek.ps1" -PromptForKey
```

保存成功后的日常启动（省略-PromptForKey）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\medical-project\scripts\start_with_deepseek.ps1"
```

验证：Windows模拟SecureString加密导出、导入解密、无明文检查均通过，临时模拟文件已删除；启动脚本语法检查通过；新增8项无联网鉴权检查测试，覆盖200/401/402/500、异常输入和连接错误脱敏。真实密钥是否保存以用户下次启动看到鉴权成功与保存提示为准。

用户通过新启动器启动后，已确认加密凭据文件存在（未读取内容），且取得真实模型响应，鉴权恢复。后续正常启动不带-PromptForKey即可使用缓存；更换密钥才需要该选项。模型调用仍可能发生网络连接失败，不应据此反复要求用户重输密钥。
