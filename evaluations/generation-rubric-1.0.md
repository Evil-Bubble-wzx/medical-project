# 回答生成验收口径1.0

回答生成与检索分别评估。不得用检索Hit@10、引用ID匹配或JSON通过率替代医学准确率。

## 自动检查

- 三段结构、返回状态与字段长度符合约定；非回答状态不能夹带未受约束的正文。
- 每个可展示陈述包含引用，编号仅来自当前检索证据包；逐字摘录必须能在提供给模型的正文内找到。
- 输入解释列出使用的字段，不能引用没有提供值的字段。
- 对显式数值剂量做启发式拦截；不代表能识别全部处方或不安全建议。
- 输出期间证据被撤回时不展示回答。解析失败、提供商失败或输出截断不展示原始未校验内容。

引用存在且摘录匹配，只说明引用形式可追踪，不能证明结论由引文充分支持。字段存在也不能证明模型正确理解了字段值。

## 人工审核，每个陈述独立记录

1. 支持性：结论能否由所引原文支持？标记充分／部分／不支持／不确定，并说明具体词句。
2. 外推边界：是否把相关写成因果、群体写成个人保证，或混淆成人与儿童、特定研究与通用指南？
3. 输入忠实性：是否准确区分患者自述、已知检查与模型推断？是否虚构病史或诊断？
4. 收敛性：证据不足、冲突、缺信息及范围外问题是否适当收敛？不能把“检索有结果”当作可以回答。
5. 引用完整性：主要陈述是否都获得充分支持，而不是同一条引文机械重复？
6. 表达：专业解释是否清楚，患者总结是否保留不确定性，且没有新增未经支持的内容？

## 本轮数据与运行

`datasets/generation-acceptance-1.0.json` 包含12个模拟开发案例，覆盖六类主题及六个边界/限制情景；不是独立临床测试集。原36题候选测试集未用于生成调参或评测。

运行 `scripts/evaluate_answer_generation.py` 会实际调用配置的模型。仅在提供商、模型和密钥均就绪时执行；未就绪生成明确的零运行报告，语义评分保持空值。API错误后停止，避免以反复重试替代问题定位。

保存的仅是此固定模拟集的结果；实际页面输入不写入这个目录。审核后另存审核者、时间、逐陈述判定与理由，不回改旧报告。没有有效模型输出时不得给出“通过率100%”的质量结论。
# 逐论断模型核验补充（2026-10-19）

新增第二次模型调用，仅观察原始模拟输入、草稿及本次证据包。逐项判断引文、疾病、人群、比较对象、结论范围和输入一致性，拒绝不受支持或不确定的句子。保留通过核验的原句，不让核验模型改写或补充内容；删减后无法形成直接回答时返回证据不足。

`semantic_support=model_judgment_only`只表示运行了模型核验，不表示人工或医学验证。生成与核验当前使用同一供应商和模型，可能存在相关错误，不是独立专家共识。核验结构不全、判定自相矛盾、调用失败或资料撤回时隐藏正文，记录错误代码。

拒答复查分为本次证据包支持拒答、可能过度拒答及无法确定。可能过度拒答必须附包内逐字摘录；核验器不能看到未召回的库内资料，因此仍需人工检查检索遗漏。8例旧拒答的开发复查中发现2例有相关库内段落未进入证据包，不能将其归为全库无资料。

人工复核应覆盖每条实际展示的论断。模型核验通过率、引用摘录匹配率、空正文拒答比例、实际回答比例和格式拦截率必须分别报告，不得合并成医学准确率。`clinical_approval`继续为false。
