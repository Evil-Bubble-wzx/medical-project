## 快速开始（Windows PowerShell）

需要 Windows、Python 3.13 和可用的宿主 pip。第一次安装需要联网；运行和测试不需要外部网络或 API 密钥。所有命令从项目根目录执行。

```powershell
.\scripts\setup.ps1
.\scripts\verify.ps1
.\scripts\start.ps1
```

`verify.ps1` 包含静态检查、自动化测试及离线评测。`start.ps1` 前台监听 `127.0.0.1:8000`，用 Ctrl+C 停止。若本机脚本执行策略限制，可对单次命令使用 `powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1`，不需要修改全局策略。

启动时若没有 `M0_DEMO_TOKEN`，脚本生成并显示当前终端的随机演示令牌。它只用于限制本机演示入口，不代表患者登录或医生授权。访问 [API 文档](http://127.0.0.1:8000/docs) 或使用下例。健康检查：`GET /health`。

真实 HTTP 启动检查：`.\.venv\Scripts\python.exe scripts/smoke_api.py`。该命令使用临时本机端口，检查结束后自动停止自己启动的进程。

在另一个终端中，把 `<启动终端显示的令牌>` 替换成令牌：

```powershell
$demoToken = '<启动终端显示的令牌>'
$payload = @{
    synthetic_only = $true
    question = '查找耳部测试条目'
    patient = @{ chief_complaint = '合成主诉'; duration = '合成时长' }
} | ConvertTo-Json -Depth 5
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/v1/demo/query' -Method Post `
    -Headers @{ Authorization = "Bearer $demoToken" } `
    -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($payload))
```

请求字段不接受 patient_id、user_id、插件或权限范围。`synthetic_only=true` 是演示输入声明，不能自动判断用户是否误填真实信息，因此仅可输入合成信息。请求不持久化；终端默认不记录访问日志。运行追踪强制关闭外部导出。

## 四类结果

| 输入 | 必要上下文 | 预期状态 |
| --- | --- | --- |
| `耳部`、`鼻部`、`咽喉` | 主诉、持续时间 | answered |
| 不匹配任何条目的问题 | 主诉、持续时间 | insufficient_evidence |
| 任意问题 | 缺主诉或持续时间 | needs_information |
| `分歧` | 主诉、持续时间 | conflicting_evidence |

这些是可重复的测试规则，不是医学决策策略；合成“冲突”来自预设标签，非医学文本冲突识别。

## 组件替换与评测

```powershell
.\scripts\evaluate.ps1
.\scripts\evaluate.ps1 -Config configs/alternative.toml
.\scripts\start.ps1 -Config configs/alternative.toml -Port 8001
```

默认配置使用 `fixture-v1` 检索器与 `extractive-v1` 生成器；替代配置使用反向排序检索器与简洁生成器。无需修改图或 API。注册表使用显式白名单；非注册 ID、外部追踪、非法超时和额外字段在启动时被拒绝。

每次评测生成独立目录，内含 `summary.json`、`results.jsonl`、`report.md`，默认不覆盖已有实验。报告包含代码、资料、数据集、依赖锁及配置指纹，插件版本、节点耗时、分层指标与逐例结果。没有真实模型调用时，token 和费用为 null，不伪造为零成本推理数据。

M0 使用 13 条合成样本验证状态路由、Recall@k、MRR、nDCG 与引用 ID 有效性。门禁要求状态、检索召回和引用 ID 有效性均达预定合成结果；不代表真实语料效果、医学正确性或临床验收。未定义金标准的无答案样本不计入召回分母。

## 目录与扩展

- `backend/app/domain`：DTO、组件 Protocol、类型化错误和共享规则。
- `backend/app/adapters`：Fake 检索、生成、重排、证据策略、验证和工程指标。
- `backend/app/graphs`：LangGraph 状态、节点、路由、限次修订与降级。
- `backend/app/application`：服务与运行清单；`backend/app/api`：本机演示 API。
- `backend/tests`：契约、流程、API 与评测测试；测试只允许本机回环连接，阻止外部网络。
- `configs`：两套可运行配置；`evaluations/datasets`：公开可提交的合成资料和案例。
- `requirements.lock`：在 Windows / CPython 3.13 环境验证的完整固定依赖版本。

增加组件：在 adapters 实现 domain 接口 → 注册白名单与配置允许值 → 增加契约测试 → 用同一数据集对比。协议已预留 Parser、Chunker、Embedder、VectorIndex、SparseRetriever，但其真实实现属于 M1/M2，当前不得宣称可入库或向量检索。

本阶段不使用 checkpoint、不保存患者信息、不实现账号权限及数据库；后续按[开发文档](docs/开发文档.md)进入 M1/M3。演示的知识 scope 过滤只是静态数据范围约束，不等于患者访问控制。

## 依赖与执行说明

项目用源码目录执行，未要求安装为 wheel；配置与评测文件位于源码仓库中。依赖版本以 `requirements.lock` 为准。重新创建环境时执行 setup，宿主 pip 只负责安装到项目 `.venv`，不修改全局包。锁文件固定版本但未包含发行包哈希，跨平台支持未验证。

Windows asyncio 需要回环套接字。如果执行环境限制本机网络，测试或服务可能在事件循环初始化时受阻，需在允许本机回环的终端运行；应用超时无法覆盖事件循环创建之前的系统限制。

技术依据：[LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)、[FastAPI Testing](https://fastapi.tiangolo.com/tutorial/testing/)。
